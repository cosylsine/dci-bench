Frozen RootFS：把工具环境固定下来

完整设计与实施记录准备与运行命令

宿主机的发行版、已安装命令和 rg 版本会改变 Agent 的可用工具。Frozen 模式把 Bash 的用户态切换到按摘要锁定的 Debian 13 RootFS，允许使用其中的全部工具和 Shell 组合；每个 Bash 调用仍经过 Bubblewrap。它固定用户态工具，仍共享宿主内核。

01 · 一次准备

持久 Bundle → 节点本地缓存

可信构建产出 OCI、RootFS tar 和工具清单；评测节点离线校验摘要、安全解包、加锁并原子发布 READY。同一内容共享只读 RootFS，样本内不下载、不安装、不重新展开。

当前 AFS 并发 flock 实测失败：Bundle 留在 AFS，缓存明确使用 /tmp/dci-bench-runtime；缓存丢失后从同一 Bundle 离线重建。
02 · 工具隔离

RootFS / corpus 只读，Scratch 独立

禁网，不挂载宿主 /usr、qrels、密钥、proc 或 GPU 设备。/tmp 映射到当前样本 scratch/tmp，写入计入同一配额；stable-rg Profile 绑定可信配置，执行 RootFS 内的 rg。

首版不额外安装 Python。失败直接报告，不自动退回宿主工具。
03 · 保留执行边界

Inspect、Pi 与自定义 read 留在宿主侧

模型通过现有 HTTP Bridge 调用工具；只有 Bash 进入隔离 RootFS。自定义 read 保留路径检查与非空正文凭据；Bash 读正文不会产生 read 凭据。候选池、预算、qrels 与评分逻辑不变；11月13日另修订中性 Prompt，Lite / Full 共用。

Lite / Full 共用 Runtime；Code Track 暂不启用 Frozen，协议继续独立。
04 · 结果可追溯

内容与策略身份贯穿结果链

镜像摘要、平台、文件树摘要和策略摘要写入 final、trace、manifest 与 fingerprint。恢复、完成批次复用和开发校准均要求身份一致，禁止跨 Runtime 混用。

评测流程

同一份query、两档嵌套候选池、相同执行预算；按阶段保留可复核记录。

  1. 01 / 资格与隔离确定20个任务

    原生中英的语料、query、qrels匹配；先去重与同源组隔离。缺格保持阻塞，译本单列。

  2. 02 / 采样开发10 · 正式50

    固定输入排序，random无放回，seed 42。Smoke取开发集1题；保存算法版本、输入摘要和选中ID，保留策略接口。

  3. 03 / 候选池Lite ⊂ Full

    保留全部正例，再按固定检索顺序补齐至200 / 1000。正例超过200的query排除并计数。

  4. 04 / 执行相同预算与隔离

    同任务/profile批处理，每题独立Pi会话。Frozen 模式在样本前验证共享 RootFS；每次 Bash 隔离执行，独立 Scratch，退出清理。

  5. 05 / 评分与归档宿主机评分

    模型提交ranked_doc_ids，qrels仅宿主机可见。逐题记录结果、费用与计时，失败和重试留痕；通过源码、协议、Runtime 身份与 hash 校验后恢复。
