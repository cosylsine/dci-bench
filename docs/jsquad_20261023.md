This release pins the official [`yahoojapan/JGLUE`](https://github.com/yahoojapan/JGLUE) repository at commit [`6f071c09316baae89c3d083a90985b4b1cb9968c`](https://github.com/yahoojapan/JGLUE/tree/6f071c09316baae89c3d083a90985b4b1cb9968c). The source is native Japanese: the official [README](https://raw.githubusercontent.com/yahoojapan/JGLUE/6f071c09316baae89c3d083a90985b4b1cb9968c/README.md) says JGLUE was built from scratch without translation, describes JSQuAD as Japanese SQuAD 1.1-style QA over Japanese Wikipedia contexts, and states the project license is CC BY-SA 4.0.

The acquisition is deliberately bounded to `train-v1.3.json` and `valid-v1.3.json`. Train and valid paragraphs form the corpus; all valid questions are retained as queries with their original paragraph as a grade-1 qrel. The test file was not downloaded or used.

## ID and label policy

JSQuAD follows the SQuAD JSON shape. QA IDs are retained byte-for-byte as query `_id` values. The source paragraphs do not expose a separate paragraph ID in this release, so each document receives a stable ID containing the split and original `(article_index, paragraph_index)` plus a SHA-256 of that position and context:

```text
passage-{split}-a{article_index}-p{paragraph_index}-{sha256(split\0article_index\0paragraph_index\0context)}
```

The original file, article index, paragraph index, title, and ID derivation are kept in document metadata. This preserves duplicate-text paragraphs as distinct source positions. Every valid query keeps the original QA-to-paragraph association as `{paragraph_id: 1}` even if an answer span is malformed; malformed spans would only be recorded under `provenance.ignored_optional_spans` and would not delete the query or qrel. The source contained no malformed spans.

The release was published with `max_positive_per_query=None` and `exclude_review_required=False`. Labels are source-derived QA seed positives, not exhaustive judgments over every corpus paragraph; unjudged documents are not asserted negatives.
