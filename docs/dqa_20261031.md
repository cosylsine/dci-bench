# DQA-Bench 中文软件问答接入审查（2026-10-31）

本次审查覆盖官方固定提交的公开样例、论文、适配器与转换验证。该来源没有进入当前原生中文覆盖。

结论是 **blocked**。官方完整包的 connectedDrive metadata 查询返回 404，当前环境对同一 Drive URL 的直连探针也不可达；官方仓库固定提交 `b2deb7a2e9267be26c35d91327e00132f4933c17` 只有公开样例。固定样例字节已经物化到授权 raw namespace；`general_knowledge_with_tags/zh.json` 有 7,490 行、7,481 个去重 answer body 和 7,490 个正关系，规模可以超过 1,000 文档/60 query，但没有逐行 native 中文来源证明；因此不能把它发布成目标 native-ZH release。

官方 README 将 DQA 描述为互联网数据收集与 LLM 生成的混合数据，并说明完整包分为 `forum_QA`、`specific_product`、`specific_instance` 等目录、各自有 train/test/validation。论文明确描述双语 QA、英中互译和 GPT-4 改写：general/forum 采用网上答案后改写，product 从手册生成问题/答案并给检索片段，instance 用 LLM 生成工具/场景问题并带工具轨迹。由此，本次没有把任何 DQA 中文行标成 `verified_native`，也没有用 translation、LLM-assisted 或 instance/tool 行填充 native coverage。

产品公开样例含 `question/answer/doc/retrieval`，适配器将 `retrieval` 保留为正文，并按 `doc` 名称保留 `source_group`；forum/general QA 可按 QA-to-retrieval 约定将原始 `answer` 作为正文，但在 metadata 中保留 `source_answer` 和原始行号。`specific_instance` 的 scenarios/tool rows 只进入 exclusions，永远不混入正文池。每个产品、类别、source split 单独处理，不能跨产品、语言或重复问答凑规模。

论文证据已固定在 reviewed receipt 的 `paper_evidence` 字段，来源为 [arXiv:2409.04475v2](https://arxiv.org/abs/2409.04475)：

- Abstract：语言模型参与数据生成、清理和改写，产物包含英中 QA。
- §3 Data Statistics：使用英译中和中译英扩展双语问答。
- §3.1 Step 2：GPT-4 改写线上社区答案。
- §3.2 Steps 2–3：模型从手册片段生成 QA，再以向量相似度选择检索片段。
- §3.3：模型生成实例问题，部分数据包含工具或场景轨迹。
