## 来源、pin、许可和语义限制

### BrowseComp-Plus

BrowseComp+ 是英文网页研究检索。官方入口是 [BrowseComp-Plus repository](https://github.com/texttron/BrowseComp-Plus)，语料卡是 [BrowseComp+ corpus card](https://huggingface.co/datasets/Tevatron/browsecomp-plus-corpus)，论文是 [BrowseComp-Plus (arXiv:2508.06600)](https://arxiv.org/abs/2508.06600)。当前适配保留 99,930 篇文档、825 个 query 和 5,023 条官方 evidence positive pairs；上游 100,195 篇中超 1 MB 的 265 篇及依赖它们的整题被记录并排除。agent 可见当前 query 与候选正文；答案、evidence/gold 和 host labels 只留在 host。语料固定到 `b27b02bc3e45511b8b82a13e6f90ce761df726f6`，query 固定到 `144cff8e35b5eaef7e526346aa60774a9deb941f`，官方仓库固定到 `046949032b0328319cc9a02663a759ec601d9402`。数据卡声明 MIT，文件 hash 和排除清单保留在源 manifest 与 parent audit。

### ArguAna

ArguAna 是英文在线辩论 argument retrieval，任务语义是检索与 query argument 形成反论证关系的文本，不是法律语料。原始入口为 [ArguAna home](https://argumentation.bplaced.net/arguana/)，BEIR archive 为 [arguana.zip](https://public.ukp.informatik.tu-darmstadt.de/thakur/BEIR/datasets/arguana.zip)，数据卡为 [BEIR ArguAna card](https://huggingface.co/datasets/BeIR/arguana)，基准论文为 [BEIR (arXiv:2104.08663)](https://arxiv.org/abs/2104.08663)。从 1,401 个有效 test query 中排除 218 个等价未标注文档歧义 query，保留 1,183 queries / 1,183 positive pairs。query 自身从保存的排名中移除；topic `group_id` 不跨 dev/test。BEIR 数据卡声明 CC-BY-SA-4.0，保留原始归属；原始论文见 [Wachsmuth et al., 2018](https://aclanthology.org/P18-1023/)。

### CQADupStack Android

Android 源是 BEIR CQADupStack 的 Android Stack Exchange 技术问答重复检索。参考 [BEIR repository](https://github.com/beir-cellar/beir)、[CQADupStack card](https://huggingface.co/datasets/BeIR/cqadupstack)、[official qrels](https://huggingface.co/datasets/BeIR/cqadupstack-qrels/blob/main/android/test.tsv) 和 [official BEIR archive](https://public.ukp.informatik.tu-darmstadt.de/thakur/BEIR/datasets/cqadupstack.zip)；BEIR 论文见 [arXiv:2104.08663](https://arxiv.org/abs/2104.08663)。完整正文 release 保留 22,998 篇文档。query `78472` 的关系在等价/歧义审查中整题排除；query `19971` 有 262 个正例，按本轮每 query 正例上限政策排除该 query，得到 697 queries / 1,432 positive pairs。Android 的 qrels 语义是重复问题检索，不能改写成软件文档生成或代码生成任务。BEIR 数据卡声明的 CC-BY-SA-4.0 及原始归属要求保留；MTEB mirror pin、fulltext release 和排除审计见主仓 receipt/docs。

### ACORD

ACORD 是英文合同条款检索。来源为 [The-Atticus-Project/acord repository](https://github.com/The-Atticus-Project/acord)、[ACORD paper (arXiv:2501.06582)](https://arxiv.org/abs/2501.06582) 和 [Atticus research page](https://www.atticusprojectai.org/research/)。下载固定到 commit `942b33a7c6fed7ead362c7c296401086f8bc0321`；嵌套 `ACORD Dataset & ReadMe.zip` 为 3,131,196 bytes，SHA-256 `c9e851456a14aed161033b856e9f40f3cc9f46cf7282c2007b143420e93a65c3`。最终只保留官方 valid 6 + test 57，排除 train 51，得到 63 queries / 676 positive pairs。原始 1–5 星映射为 raw grade 0–4；canonical relevance 为 `max(raw_grade - 1, 0)`，即 3/4/5 星分别为 relevance 1/2/3，1/2 星保留在 host judgments 但不进入 positive qrels。query 按原始 query/parent identity 分组；DCI seed 42 的 dev10/test50 是本项目采样，不是官方 ACORD scoring split。数据声明 CC BY 4.0，repository wrapper 为 MIT；两者均由 receipt 保留。

### CEDAR

CEDAR 是中文普通话辩论论证数据，适配任务是显式论证关系检索。来源为 [CEDAR repository](https://github.com/VelikayaScarlet/CEDAR) 和 [ACL 2026 paper](https://aclanthology.org/2026.acl-long.238.pdf)。archive 固定到 commit `cb46d01672c9f1fd203eca6ee57bca4f4bc9fbb7`，原始归档、Git pin、SHA-256 和 Apache-2.0 信息见 [CEDAR 接入记录](cedar_20261031.md)。reviewed source 保留 25,794 docs / 241 queries / 463 positive pairs：query 是关系 target claim，document 是显式 relation source 的 claim/evidence；support 与 against 都是正相关关系，不能从同 topic 或对立立场推断 qrels。

reviewed 转换整题排除所有 `equivalent_unlabelled_document` query，按完全相同 decoded text 合并 alias 并保留原始 annotation/provenance；每个 topic 确定性保留一个 query 以保证 group isolation。query claim 同时可能是 corpus document，最终数据准备会根据保留的 source annotation/alias 映射排除 query 自身；未标注 document 不作 negative。原始 occurrence release 的 `review_required` 与 reviewed release 的自然 `labels_ready` 均保留，不把后者误报为已完成 ranked pool。

## 统一 pool 和 suite 边界

主准备脚本是 [`scripts/prepare_gapfill_20261031.py`](../scripts/prepare_gapfill_20261031.py)，其 `RELEASES` 映射是最终 release 身份的权威入口。目标输出如下：

- source releases：
  - BrowseComp+：`/mnt/afs2/202609/embedding_models/dci-bench/eval_data/dci_expansion_20261014_v1`
  - ArguAna：`/mnt/afs2/202609/embedding_models/dci-bench/eval_data/pipeline_v1/gapfill_arguana_en/20261031_v2`
  - Android：`/mnt/afs2/202609/embedding_models/dci-bench/eval_data/pipeline_v1/gapfill_android_en/20261031_v2`
  - ACORD：`/mnt/afs2/202609/embedding_models/dci-bench/eval_data/pipeline_v1/gapfill_acord_en/20261031_v3`
  - CEDAR：`/mnt/afs2/202609/embedding_models/dci-bench/eval_data/pipeline_v1/gapfill_cedar_zh/20261031_v2`
- pool/root：`/mnt/afs2/202609/embedding_models/dci-bench/eval_data/benchmark_gapfill_20261031_v1`
- final suite：`benchmark_v2_20261031_v1`（由主线程按 benchmark-v2 规范发布）
- 采样：固定 seed 42，dev 10、test 50；smoke 只从 dev 取 1 条
- ranked pools：每源 Lite 200、Full 1000，Lite 必须是 Full 的子集，并保留全部已标注正例；排名召回与正例注入后的覆盖率分别统计；两档 equal budget
- labels：qrels/host labels 只在 host；agent 只看到该任务允许的 candidate documents

中间源池 200/1000 分别记录排名与正例注入；最终 benchmark suite 从 Full 池重新构造嵌套 Lite，并审计实际子集关系。

当前没有对这些五源运行模型评测。实际 KaLM 编码仅用于数据准备阶段的排名池构建；不能把编码、pool `_COMPLETE` 或 source release `labels_ready` 写成 benchmark score 或 suite 完成。

最终目标是数据池审计通过后的 18/20 tasks；该数字是目标边界，不是当前完成数。主线程仍需补齐：五源实际 ranking/pool 的 `_COMPLETE` 与 hash、Lite⊂Full 证据、query/group split audit、host-only labels 检查、最终 suite catalog 与动态路径快照。网页报告由主线程更新。

## 尚未填入的中文缺口

- `software_zh` 暂不接入。公开 DQA 样例有 7,490 queries、7,481 answers、7,490 QA rows，但论文描述其来源包含翻译/生成，当前没有逐行 native Chinese provenance 证明；它保持 blocked，不能作为中文软件文档/技术问答检索源。
- `enterprise_zh` 暂缓。当前没有通过同任务语义、原生中文、至少 1,000 candidates / 60 isolated queries 和可审计 qrels 的企业知识检索来源；大学招生、电商商品搜索、产品支持或通用网页数据不能直接等同企业内部知识。
- `argumentation_zh` 已由 CEDAR 提供候选源，但仍须完成上述 ranked pool audit 后才可进入最终 suite。

本文件描述的是数据接入和待验收边界，不包含模型调用、评测分数或网页报告结论。

## 可复现数据准备命令

本轮沿用本地 `KaLM-embedding-multilingual-mini-instruct-v2_5`，weight identity 为 `59c9624a274740f8cf9d7aa195d6d599b4e3fabf8e47106be112ebca1ed6d2e0`。最大编码长度 8,192 token，document prompt 为空、query prompt 沿用已冻结配置，归一化向量；正文文件保留完整，编码截断量另记在 `encoding_audit`。实际排名和正例注入分别留痕。BrowseComp+ batch 32 的失败日志保留，重试使用 batch 8；Android、ACORD 和 CEDAR 使用 batch 2，与网页编码共享剩余显存。batch 改变会进入独立 embedding cache namespace，不声称复用失败批次的 shard。

已导出的源位于 `benchmark_gapfill_20261031_v1/source`；排序与构池命令如下。已完成的 pool 只校验和复用，catalog 与最终 suite 拒绝覆盖。

```bash
cd /mnt/afs/250010100/zxp/dci-bench
export NVIDIA_DRIVER_CAPABILITIES=compute,utility
export LD_LIBRARY_PATH=/lib/x86_64-linux-gnu:/usr/lib/x86_64-linux-gnu:/mnt/afs/250010100/miniconda/envs/retriever/lib
RANK_PY=/mnt/afs/250010100/miniconda/envs/retriever/bin/python
for source in gapfill_arguana_en gapfill_browsecomp_plus_en; do
  "$RANK_PY" scripts/prepare_gapfill_20261031.py rank-pools --source "$source" --batch-size 8
done
for source in gapfill_android_en gapfill_acord_en_v3 gapfill_cedar_zh_v2; do
  "$RANK_PY" scripts/prepare_gapfill_20261031.py rank-pools --source "$source" --batch-size 2
done
DATA_PY=/mnt/afs/250010100/miniconda/envs/dci-bench/bin/python
EVAL_ROOT=/mnt/afs2/202609/embedding_models/dci-bench/eval_data
"$DATA_PY" scripts/prepare_gapfill_20261031.py catalog
"$DATA_PY" scripts/prepare_benchmark_v2.py prepare \
  --catalog "$EVAL_ROOT/benchmark_gapfill_20261031_v1/catalog.json" \
  --config configs/benchmark_v2.json \
  --output "$EVAL_ROOT/benchmark_v2_20261031_v1"
"$DATA_PY" scripts/prepare_benchmark_v2.py audit \
  --output "$EVAL_ROOT/benchmark_v2_20261031_v1"
```

为保持 ArguAna topic 整组隔离，采样器在既有 64 次贪心尝试全部失败后，仅对无法填满配额的当前任务启用整组组合选择；不会拆分 group 或借用其他任务的数据。`export_dci` 只将明确的分组字段提升到 query 行，答案与 judgments 仍为 host-only。与旧 13 任务的抽样一致性由最终 suite 对比单独验收。
